It's been a while since I wrote in this website of mine. I've been
working on this project for a while now, mostly on the QuickTime/MP4
parser and renderer.

I've been very interested in video technology so I've been reading quite
a bit about it. Yes it's what I do at work anyway but it's turned into a
hobby as well. Xray began as a way for me to understand MP4 files.

Right now I'm able to parse maybe half(?) of the atoms defined in the
QuickTime spec. Rendering is still catching up but I can view the atoms
as a tree and the binary contents of atoms I haven't written a proper
renderer for.

The part I really enjoyed was figuring out that I needed to have these
utility functions to read integers, floats, etc instead of reading the
bytes and parsing them directly for each atom. These utility functions
can be reused for other parsers that I'll be writing so I'm very glad
about that.

A big shock for me came when I realised that the MP4 spec for the `meta`
box has a very slight but profound difference to the `meta` atom defined
in the QuickTime spec; the `meta` box is a full box, with `version` and
`flags` fields but the `meta` atom does not have these fields. This
caught me off guard because I was assuming that the MP4 spec didn't
modify any of the atoms specified in the QuickTime spec.

I spent several hours trying to figure out why the parser failed for a
.mov file but worked for an .mp4 file. This has resulted in a parser that
checks if the actual number of bytes read is the expected number. I'm
glad it wasn't some tricky logical bug requiring a massive refactor. Also
pleasantly surprised how easy it was to subclass the QuickTime parser and
modify just the parser for the `meta` box in the MP4 renderer.
